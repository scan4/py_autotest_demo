# py_autotest — AI 自动化测试平台

面向 Python Web 后端（HTTP API）的自动化测试平台：**从源码静态分析出发，LLM 生成可执行测试用例，真实 HTTP 执行，失败结果结构化回灌 LLM 诊断修正，多轮自动迭代，最终在 git 分支隔离下由 AI Agent 自动修复确认的系统缺陷（人工审阅 merge）**。

## 架构与闭环

```
源码 ──AST──> 调用图/功能点档案 ──LLM──> 测试用例（代码指纹缓存）
                                              │
         OpenAPI 契约（登录端点自动识别）       ▼
                                              评审 Agent（read_source）
                                              ▼
被测服务 <──真实 HTTP 执行── 意图断言 + 资源工厂 + 凭证链路
              │
         失败三分类（用例缺陷 / 疑似系统缺陷 / 环境问题）
              │
         回灌 Agent（读源码复核 → 修正用例 → 多轮迭代收敛）
              │
         疑似缺陷登记注册表 ──> 修复 Agent（git 分支隔离）──> 人工审阅 merge ──> 重放验证
```

## 核心特性

- **静态分析**：AST 构建调用图，按入口拆分功能点；接口契约"信号竞争"——Django urls.py / 装饰器路由静态解析与 OpenAPI 运行时探测互为兜底，operationId 四层匹配关联功能点，零框架识别成本
- **可执行用例生成**：LLM 按功能点档案生成带真实 method/url/body 的 HTTP 用例；代码指纹缓存避免重复调用；评审 Agent 可读源码把关
- **真实执行与断言**：意图断言（按用例意图而非预期状态码精确匹配，四级判定消除误报）；测试数据自动准备——OAuth2 登录换 token 替换凭证占位符、资源工厂预创建真实资源
- **失败三分类**：用例缺陷（自动修）/ 疑似系统缺陷（用例保留作复现依据，严禁改预期掩盖 bug）/ 环境问题（凭证链路内置解决）；规则初分类 + LLM 读源码复核
- **多轮迭代**：执行→回灌→再执行自动循环，轮次间携带"已证伪方案"证据链记忆，无改进提前停止
- **AI 自动修复**：function calling 工具循环（read_source / edit / run_tests / finish），git 分支隔离、复现请求锁定、验收失败自动回滚、人工审阅 merge
- **可观察性**：失败逐条附分类标签与提示；资源工厂日志透出；无凭证执行显式警告

## 快速开始

```bash
# 安装依赖
pip install -r requirements.txt

# 启动平台（端口 8001）
uvicorn pyst.webapp:app --host 0.0.0.0 --port 8001

# 浏览器打开 http://localhost:8001
# 步骤：选择被测项目目录 → 分析 → 接口探测 → 生成用例 → 评审 → 执行 → 失败回灌/多轮迭代
```

被测服务需另行运行（真实 HTTP 执行需要可达的 base_url；需鉴权的接口在执行前填入测试账号密码，平台自动登录换取 token）。

## 测试

```bash
python -m pytest tests/ -v
```

83 条回归测试，覆盖执行器断言、失败分类、修复 Agent 工具循环（LLM 全 mock）、用例库去重、路由级集成等；每条测试对应一次真实的边界场景。

## 目录结构

```
pyst/
├── core/          # 静态分析：AST 索引、调用图、功能点拆分、接口契约提取、用例生成
├── eval/          # 执行与 Agent：executor（真实 HTTP+断言）、assertions（意图断言）、
│                  # feedback（失败分类+回灌）、fixer（AI 修复）、coverage（盲区检测）
├── llm/           # LLM 客户端（function calling）
├── storage/       # 用例库与缺陷注册表（SQLite）
├── webapp.py      # FastAPI 服务与路由
└── static/        # 前端单页
tests/             # pytest 回归测试
```

## 设计要点

- **占位符协议**：LLM 受 token 预算约束无法输出真实超长数据，以占位符表达意图，执行器按特征归一化展开为真值——生成方与执行方职责分离
- **两种 Agent 记忆策略**：修复 Agent 采用完整对话历史 + 工作区双载体（任务状态在被测代码里）；回灌迭代采用摘要注入的负记忆（任务状态在用例集里）
- **失败分类原则**：仅"用例缺陷"自动修正；疑似系统缺陷的用例原样保留作为复现依据——修改预期以通过测试会掩盖真实缺陷
- **AI 修改代码的安全边界**：分支隔离、复现请求锁定、验收失败自动回滚、人工审阅 merge

## 已知边界

- 单请求用例无法表达请求链（前置登录、先创建后更新），资源工厂是最小可用方案，多步用例在计划中
- 断言二阶段（响应体字段级校验）推进中；MCP 工具层未做
